# 타이포·생성·검수 기준

## 시리즈 디자인

공공 블루 입체형의 예시 팔레트는 배경 #FAFAF7, 제목 #142B49, 강조 #2864DA, 보조 #EAF1FC, 본문 #3D4B5E다. 외곽 여백은 약 7%, 모바일 카드의 화면비는 4:5를 후보로 쓴다. 사용자 승인 스타일과 화면비를 우선한다.

첫 장의 생성물을 후속 장의 스타일 참조로 사용한다. 표지와 참여 장에는 작은 입체 오브젝트를, 분석 장에는 숫자·그래프를 중심으로 배치한다. 마지막 장의 배경색 반전은 참여 정보 구분에 활용할 수 있다.

## 모든 프롬프트에 넣을 타이포 문구

> 같은 의미 위계의 텍스트는 영역이 달라도 글씨 크기와 굵기를 균일하게 유지한다. 모든 제목은 같은 기준 크기, 모든 본문은 같은 기준 크기, 같은 종류의 수치와 레이블은 각각 동일 크기를 적용한다. 긴 문구도 글씨 크기를 개별 축소하는 대신 영역 폭과 줄 수를 조정한다. 지정된 줄바꿈을 우선하고 추가 줄바꿈은 한국어 의미 단위와 어절 경계에서 한다. 조사·어미는 앞 어절과 함께 배치한다. 숫자와 단위, 날짜, 서비스 주소는 한 덩어리로 유지한다. 제목 행간 1.2, 본문 행간 1.5를 기준으로 하고 글자와 도형의 안전 여백을 확보한다.

카피와 디자인 설명을 분리한다. 제목·본문·수치·레이블·주석 역할별 크기와 위치를 명시하고 임의 문구 생성을 허용하지 않는다. 원문에 있는 혼합 서비스명은 검사기 경고를 피하려고 변경하지 않는다.

## 생성 절차

1. 연결된 Codex 실행기의 버전·로그인·지원 옵션을 확인한다. 인증을 다른 런타임에서 복사하지 않는다.
2. 장별 프롬프트를 저장·검사한다. 검증 오류를 고친 뒤 실행한다.
3. 첫 장을 생성해 직접 보고 나머지를 동일 스타일로 순차 생성한다.
4. 상태·출력 경로·생성 ID·캐시 여부를 기록한다. 성공 장은 덮어쓰지 않는다.
5. 실패 시 로그와 파일부터 확인한다. 인증 오류는 재로그인 문제로 분리하고 API 과금 경로로 자동 전환하지 않는다.

## 사실과 시각 검수

- 모든 이미지의 한글·숫자·단위·기간·요일·참여 경로를 원고와 대조한다.
- 같은 수준의 레이블과 질문이 동일 크기인지 확인한다. 긴 문구만 줄어들거나 어절이 갈라지는지 확인한다.
- 누적·월간 값은 기준을 각각 표시한다. 그래프의 축·순서·막대 높이를 원자료와 대조한다.
- 서비스 주소와 설문 참여 경로를 구분한다. 실제 경로가 메뉴 이동이면 불필요한 QR·URL을 만들지 않는다.
- PNG 유효성·실제 크기·요청 장수와 프롬프트 수를 코드로 검사한다. 근사 화면비 원본을 강제로 늘리지 않는다.
- 오류는 프롬프트를 수정해 해당 장을 재생성한다. 이미지 위에 글자를 덧칠하지 않는다.

## 전달 묶음

PNG, 프롬프트, 기획안, manifest, 검수 기록만 ZIP에 넣는다. 인증·실행 로그의 개인 정보는 제외한다. 기관 내부 원고·이미지는 공개 스킬 업데이트와 분리한다.
